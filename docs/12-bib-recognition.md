# 号码牌识别与筛选

状态：已批准的实施基线
更新日期：2026-08-31

## 1. 目标与边界

号码牌功能用于学校活动照片中的印刷阿拉伯数字识别。上传者设备自动给出号码候选，上传者、审核员或管理员确认后，口令相册观众可以输入号码精确筛选相关照片。

固定边界如下：

- 自动识别只是辅助，不能未经人工确认直接进入公共搜索。
- 照片发布不等待 OCR 或确认；号码确认后独立加入搜索索引。
- 号码确认后按当前映射规则自动派生年级和班级属性，观众可按年级或“年级 + 班级”筛选。
- 仅识别新上传照片，不对历史照片自动补扫。
- 历史照片可由内部人员手工补录号码。
- OCR 无候选不代表照片没有号码；“无号码”必须由有权限人员明确确认。
- 号码牌管线不识别人脸、姓名、手写号码、球服号码或其他身份特征；ADR-012 批准的未来人脸候选找图是独立功能，不复用 OCR 候选、规则、Worker、密钥或索引。
- 图片始终在上传者设备本地推理；香港 API 只通过 HTTPS 接收号码元数据、置信度和框坐标，号码仅在请求内存中短暂存在并在落库前加密。
- 号码牌功能不调用阿里云或其他第三方托管 OCR/AI 服务；未来 IMM 人脸处理不得接收号码候选或改变本地 OCR 边界。

## 2. 相册级开关

号码识别与观众搜索使用两个独立设置：

- `bibRecognitionEnabled`：上传端执行本地 OCR 并允许后台号码标签。
- `bibSearchEnabled`：观众端显示号码搜索入口。

两项默认关闭。启用观众搜索必须同时满足：

1. 相册为 `password` 访问模式；
2. 已配置至少一条有效号码规则；
3. 号码数据密钥与搜索密钥已配置；
4. 自动识别若对外标为可用，已通过本文件的样本验收门槛。

相册切换为公开访问时自动关闭 `bibSearchEnabled`，但不会删除已确认标签。重新改回口令相册后需要管理员再次明确开启。

## 3. 可配置号码规则

### 3.1 规则模型

规则不允许使用原始正则表达式，采用结构化模式：

- 一个相册包含一个 `BibRuleSet`。
- `BibRuleSet` 包含一条或多条 `BibPattern`，模式之间为 OR。
- 每条 `BibPattern` 固定总位数，允许 1–12 位。
- 每条模式包含零个或多个 `BibConstraint`，约束之间为 AND。
- 每个约束指定 1 开始的位置、连续宽度，以及一个或多个固定宽度的闭区间；区间之间为 OR。
- 未被任何约束覆盖的位置允许任意 `0–9`。
- 约束可以重叠；候选号码必须同时满足所有重叠条件。
- 号码始终作为字符串处理，保留前导零；区间端点必须与约束宽度一致。

### 3.2 示例

6 位号码，前三位允许 `101–112`、`201–212`、`301–312`、`401–406`：

- 模式总长：6；
- 约束起始位：1；
- 约束宽度：3；
- 允许区间：上述四段；
- 第 4–6 位没有约束，因此允许任意三位数字。

若需要限制第 2–3 位，则新增起始位为 2、宽度为 2 的约束。若同一相册还允许另一种长度，则新增另一条 `BibPattern`。

### 3.3 配置校验

- 起始位与宽度必须落在模式总长度内。
- 每个区间必须全为数字、固定宽度且起点不大于终点。
- 重复区间和完全被包含的区间在保存时规范化合并。
- UI 提供“输入测试号码”即时验证和逐条件结果，不要求管理员理解正则。
- 没有任何号码可通过的冲突规则允许保存为草稿，但不能开启识别或搜索，并明确显示错误。

规则保存后生成递增 `ruleVersion`。规则改变时，系统只重新校验已有号码元数据，不重新读取图片：仍符合规则的标签更新版本；不符合的确认标签转为 `needs_review` 并立即移出公共搜索。

## 4. 年级与班级派生规则

### 4.1 属性选项

相册配置两个固定维度：`grade`（年级）和 `class`（班级）。每个维度包含管理员可排序的选项：

- 选项拥有不可变内部 ID、可编辑显示名称和排序；
- 示例年级选项：内部 ID `grade-7`，显示“初一”；
- 示例班级选项：内部 ID `class-01`，显示“一班”；
- 不导入学生姓名、学号名单或号码到个人身份映射。

### 4.2 映射模型

`BibAttributeMapping` 将号码的指定连续位置映射到一个年级或班级选项：

- 指定维度、起始位、宽度和一个或多个允许闭区间；
- 指定唯一输出选项；
- 同一映射内区间为 OR；多条映射独立匹配；
- 未命中映射时该维度为空，不猜测、不继承其他号码结果；
- 同一号码同一维度若命中不同输出，配置视为冲突，不能保存为可启用版本。

示例：

- 第 1 位为 `1` → 年级“初一”；
- 第 1 位为 `2` → 年级“初二”；
- 第 2–3 位为 `01` → 班级“一班”；
- 第 2–3 位为 `02` → 班级“二班”。

属性映射只在号码通过合法性规则并被人工确认后执行。确认、修正号码时同步计算；号码改变时替换旧属性；删除号码时同步删除其属性。

### 4.3 多号码照片与筛选语义

每个确认号码分别保存自己的年级/班级。照片的年级或班级筛选使用“存在同一确认号码标签满足条件”语义：

- 选择年级时，照片中任一确认号码属于该年级即可匹配；
- 选择年级 + 班级时，必须由同一个确认号码同时派生该年级和班级；
- 不允许将照片中不同号码的年级与班级交叉组合；
- 观众端必须先选择年级，才可选择该年级下的班级，不提供全局班级单独筛选；
- 年级/班级过滤可以与相册一级分类同时使用，但与精确号码搜索使用互斥模式。

### 4.4 映射版本与重算

属性配置保存后生成递增 `mappingVersion`。修改选项名称只更新展示；修改位置、范围或输出选项时建立持久重算任务，对全部确认号码解密后重新派生，不读取图片。

- 只使用当前 `mappingVersion` 的属性进入观众筛选；
- 重算期间后台显示“属性更新中”，观众属性筛选暂时关闭，精确号码搜索仍可使用；
- 未命中年级时号码仍可精确搜索，但不进入年级/班级筛选；
- 命中年级但未命中班级时可进入年级筛选，不能进入班级筛选；
- 冲突映射在保存前拒绝，不能用“第一条优先”隐藏歧义。

## 5. 浏览器本地 OCR

### 5.1 运行时

- 使用官方 `@paddleocr/paddleocr-js`，模型选择 `PP-OCRv6_tiny_det` 与 `PP-OCRv6_tiny_rec`。
- 使用 SDK Worker 模式，OCR、OpenCV.js 和 ONNX Runtime Web 均在专用 Worker 中运行。
- Chromium 在运行时支持时优先 WebGPU；Safari及其他设备使用 WASM。
- 模型、Worker、OpenCV 和 WASM 均固定版本并自托管于 `/assets/models/bib-ocr/{modelVersion}/`。
- 必须显式配置本地资源路径，禁止 SDK 回退到第三方 CDN。
- 只有启用号码识别的相册进入上传/审核页面时才懒加载，观众端不加载 OCR 运行时。

### 5.2 照片处理顺序

1. 照片 Worker 完成方向修正并生成 480/960/1920 派生图。
2. 480/960 立即进入上传队列；发布流程不等待 OCR。
3. 1920 工作图交给 OCR Worker，单设备同一时间最多识别一张照片。
4. OCR 返回文本框、原始文字和置信度后立即释放图像资源。
5. 只保留数字化、长度和规则可接受的候选，去重后最多 8 个。
6. 候选通过 HTTPS 提交香港 API，进入 `suggested`，不进入公共索引。

OCR 无结果、失败或设备不支持时，不影响照片上传和发布；上传卡片必须显示“未识别到候选，待复核”，并同时提供“手工添加号码”和“确认无号码”。系统不得自动创建号码、年级、班级或无号码结论。

### 5.3 候选规范化

- 全角数字转换为 ASCII 数字；允许去除数字之间的空白。
- 不静默进行 `O→0`、`I→1`、`S→5` 等字母替换。
- 非纯数字、长度不符或不满足任何模式的结果不进入常规候选。
- 同一照片中相同号码且框重叠度较高的结果合并，保留更高置信度。
- 置信阈值不是管理员配置项，由授权样本基准统一校准并随模型版本记录。

## 6. 人工确认工作流

### 6.1 权限

- 上传者可确认、修改、拒绝或手工添加自己上传照片的号码。
- 审核员和管理员可操作相册内全部照片。
- 观众不能查看候选、框位置、置信度或号码目录。

### 6.2 标签状态

| 状态 | 含义 | 是否可搜索 |
| --- | --- | --- |
| `suggested` | OCR 候选，尚未人工确认 | 否 |
| `confirmed` | 人工确认或手工添加且符合当前规则 | 是 |
| `rejected` | 人工明确拒绝的候选 | 否 |
| `needs_review` | 规则改变后不再有效或发生冲突 | 否 |

修改 OCR 候选等同于拒绝原候选并创建一条人工来源的确认标签，保留不含号码明文的审计关系。一张照片可以确认多个不同号码。

确认号码后自动写入当前年级/班级派生属性。审核页面允许：框选候选、快捷确认、键盘录入、删除标签，以及给当前选中的多张照片添加同一号码。任何确认值都必须通过当前规则。

### 6.3 照片级复核结论

号码标签状态之外，每张启用识别的照片拥有 `BibReviewDecision`：

| 状态 | 含义 |
| --- | --- |
| `pending` | 尚未有人对“有无号码”作出明确结论 |
| `numbers_confirmed` | 至少有一个人工确认号码 |
| `no_number_confirmed` | 人工明确确认照片中没有号码 |
| `needs_review` | 规则变化、冲突或数据修复要求重新复核 |

规则固定如下：

- OCR 没有候选、OCR 失败或人工拒绝全部候选后仍是 `pending`，绝不自动变成无号码；
- “确认无号码”只允许在没有确认号码时执行，并在同一事务中拒绝剩余候选；
- `no_number_confirmed` 后迟到的 OCR 候选不得改变人工结论，也不得创建号码；
- 手工添加或确认号码会清除无号码结论并改为 `numbers_confirmed`；
- 删除最后一个确认号码后回到 `pending`，不能自动改为无号码；
- 上传者可给自己照片确认无号码；审核员/管理员可操作全部照片；支持批量“确认无号码”；
- 无号码照片保留在普通相册流中，但不进入号码、年级或班级筛选。

## 7. 数据模型与加密

### 7.1 配置实体

- `AlbumBibConfig`：相册、识别/搜索开关、当前规则版本、模型版本和更新时间。
- `BibPattern`：模式 ID、总位数、排序和启用状态。
- `BibConstraint`：模式、起始位、宽度和排序。
- `BibAllowedRange`：约束、起点字符串、终点字符串。
- `BibAttributeOption`：`grade`/`class` 维度、不可变 ID、显示名和排序。
- `BibAttributeMapping`：维度、起始位、宽度、允许区间、输出选项和排序。

### 7.2 标签与复核实体

`MediaBibTag` 保存：相册 ID、媒体 ID、号码密文、blind index、状态、来源、置信度、归一化四边形、规则版本、模型版本、派生 `gradeOptionId`/`classOptionId`、映射版本、创建者、确认者和时间。

`MediaBibReview` 保存照片 ID、`BibReviewDecision`、决定人、决定时间和最后变更原因。它不保存号码内容。

- 号码使用独立应用数据密钥进行 AEAD 加密，不在 PostgreSQL 或备份中保存明文。
- 精确搜索使用 `HMAC(searchKey, albumId + normalizedNumber)` 的 blind index。
- 数据密钥和搜索密钥独立于会话/CDN 密钥，并记录密钥版本以支持轮换。
- 审计日志只保存标签 ID、状态变化和操作者，不保存号码、搜索令牌或 OCR 原文。

相册结束 30 天后清理 `suggested`、`rejected` 和未解决的非确认标签；`confirmed` 标签随相册保留，直到永久删除相册/照片。

## 8. API 契约

### 8.1 后台

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/v1/albums/{id}/bib-config` | 返回规则、版本、开关和模型状态 |
| `PUT /api/v1/albums/{id}/bib-config` | 校验并保存完整规则配置，触发元数据重校验 |
| `POST /api/v1/albums/{id}/bib-config/test` | 测试输入号码并返回逐模式/约束结果 |
| `POST /api/v1/media/{id}/bib-candidates` | 上传者批量提交本地 OCR 候选，幂等 |
| `POST /api/v1/media/{id}/bib-tags` | 手工添加符合规则的确认号码 |
| `POST /api/v1/media/{id}/bib-tags/{tagId}/confirm` | 确认候选，可同时提交修正值 |
| `POST /api/v1/media/{id}/bib-tags/{tagId}/reject` | 拒绝候选 |
| `DELETE /api/v1/media/{id}/bib-tags/{tagId}` | 删除有权限的标签 |
| `POST /api/v1/media/bib-tags/batch` | 为选中照片批量添加同一确认号码 |
| `POST /api/v1/media/{id}/bib-review/no-number` | 人工确认该照片无号码并拒绝剩余候选 |
| `POST /api/v1/media/{id}/bib-review/reset` | 撤销照片级结论，恢复待复核 |
| `POST /api/v1/media/bib-review/no-number/batch` | 批量确认选中照片无号码 |

候选坐标使用相对图片宽高的 0–1 四边形坐标，不提交裁剪图。候选提交最多 8 条，服务端再次验证格式和规则。

配置读取/更新同时包含年级、班级选项和映射。测试接口返回：号码是否合法、命中的合法性规则、派生年级/班级和命中的映射 ID。

### 8.2 观众搜索与属性筛选

`POST /api/v1/public/albums/{slug}/bib-search` 使用 JSON 请求体接收一个号码和可选分页游标。服务端依次校验口令会话、相册开关、号码规则和限流，再计算 blind index，返回 `confirmed + published` 照片的现有公共媒体表示。

- 搜索只做精确匹配，不使用编辑距离或相近号码推荐。
- 每页最多 60 张，继续使用签名游标。
- 返回结果不回显其他号码、候选、置信度或框位置。
- 无匹配、只有未发布匹配或号码不存在时使用相同空结果语义。
- 搜索号码不写 URL、访问日志、统计事件或 SSE。
- 新确认标签或标签失效只发送通用 `media.bib.updated` 事件，客户端在当前搜索会话中重新查询；事件不包含号码。

`POST /api/v1/public/albums/{slug}/bib-attributes-filter` 接收 `gradeOptionId`、可选 `classOptionId`、可选分类和分页游标：

- `gradeOptionId` 必填；提供班级时必须与同一确认号码标签上的年级同时匹配；
- 只查询 `confirmed + published + 当前 mappingVersion` 标签；
- 返回普通公共媒体表示，不返回每张照片的号码或号码框；
- 无号码、待复核、属性缺失和旧映射版本照片均不进入结果；
- 公共相册配置只返回已配置年级/班级选项及排序，不返回号码范围、匹配数量或学生信息。

## 9. 前端体验

### 9.1 规则与属性编辑器

管理员通过卡片式模式/约束编辑器配置总位数、位置和区间。界面使用 1 开始的位号，显示一条数字槽位预览，未约束位标为“任意”。“年级/班级映射”页复用位置与区间选择器，并为每条映射选择输出名称。保存前展示冲突检查和示例号码的合法性、年级、班级结果。

### 9.2 上传与审核

- 上传队列分开显示 OCR 活动和照片级复核：OCR 活动为未启用、等待 OCR、识别中、识别失败；照片级复核固定为待复核、有确认号码、确认无号码、需复核。单条候选仍按 `suggested`、`confirmed`、`rejected`、`needs_review` 独立展示，不能用“已确认”同时概括候选和整张照片。
- 照片卡片显示候选号码 chip 和可切换的框覆盖层；不以置信度颜色代替文字状态。
- OCR 下载/初始化只显示一次，后续照片显示单张进度。
- 识别失败有“手工添加号码”，不能让失败阻止媒体完成。
- 审核员发布照片时可顺手确认候选，但发布按钮不强制等待号码处理。
- 每张照片必须提供独立“无号码”动作；OCR 无结果显示待复核，而不是绿色完成状态。
- 后台筛选增加：待复核、有确认号码、确认无号码、需复核、年级和班级。

### 9.3 观众

口令相册启用搜索时，在相册头部/分类下方显示“输入号码找照片”。输入框根据当前规则给出长度示例，但不展示合法号码列表或自动补全。

号码仅保存在当前页面内存；刷新后需要重新输入。清除搜索恢复普通直播流。搜索结果仍可打开灯箱，并遵循相册下载开关。

观众可切换“按号码”与“按年级班级”两种模式。属性模式先选择年级，再显示该年级可用班级；允许只按年级筛选，不允许脱离年级单独选择班级。属性标签只用于筛选，不默认显示在照片卡片或灯箱上。

## 10. 安全与隐私

- 号码可能映射到未成年人身份，按个人标识符保护，即使活动称其为临时号码。
- 不导入学生姓名、花名册或号码到个人身份映射；允许配置号码到年级/班级类别的确定性映射。
- 只有口令相册可向观众开放搜索；不支持跨相册搜索。
- 每个访客会话和每日轮换 IP-HMAC 每 10 分钟最多 30 次搜索。
- 服务端日志、错误、分析、SSE 和 Referrer 不得包含搜索值或解密号码。
- 模型资源是公开静态软件资产，不包含学校照片或识别数据。
- 授权评测照片与标注保存在 Git 外的受控本地目录，未经学校批准不得上传第三方训练平台。

## 11. 费用与性能

号码识别不新增阿里云产品。新增费用只可能来自：OCR 模型/运行时文件的 OSS 标准存储、上传请求和上传者首次加载时的 CDN 基础下行。

- 模型和运行时压缩总量预算不超过 35MB，哈希路径缓存一年。
- 上传端每个模型版本只下载一次；不在观众端加载。
- 暖机推理 p95：桌面 Chromium 不超过 3 秒，移动设备/Safari WASM 不超过 8 秒。
- OCR 与照片上传并行，不能推迟 480/960 上传或阻塞主线程。
- 不增加任何新的照片 OSS 派生对象；框坐标和号码标签只占少量 PostgreSQL 元数据。

## 12. 样本与验收门槛

学校提供至少 200 张已授权、具有代表性的照片，存放于 Git 外，并标注每个可读号码和四边形。样本至少包括：

- 120 张含清晰号码的常规照片；
- 40 张多人、倾斜、部分遮挡、暗光或运动模糊照片；
- 40 张没有有效号码但包含背景数字的负样本。

“可读号码”定义为人工在平台 1920 派生图上能够无歧义读出的号码。正式启用自动候选必须达到：

- 可读号码候选召回率不低于 90%；
- 无有效号码照片平均错误候选不超过 1 个；
- 单张照片候选数量中位数不超过 3；
- 多号码照片可分别确认并被精确搜索；
- 没有任何未确认候选进入公共搜索。
- 无号码负样本不会自动生成确认号码、年级、班级或无号码结论，人工确认无号码后保持普通相册可见且不进入属性筛选。

置信阈值在固定模型、固定规则和上述样本上扫描校准，结果连同模型哈希、浏览器和设备记录。若未达门槛，手工标签与精确搜索仍可交付，自动候选保持禁用/实验状态；自定义模型训练另行规划。

## 13. 测试范围

- 规则属性测试：不同长度、前导零、任意位置、重叠约束、多区间、模式并集、无解规则和版本变更。
- 派生属性测试：任意位置映射、同维度冲突、缺失映射、映射版本重算、多号码同照片，以及年级+班级必须来自同一号码标签。
- OCR 测试：多号码、背景年份、边缘裁切、倾斜、遮挡、全角数字、字母混淆、失败与取消。
- 无号码测试：OCR 无候选、全部候选被拒绝、明确确认无号码、迟到候选、撤销无号码、添加号码自动清除无号码和删除最后号码回到待复核。
- 权限测试：上传者仅操作自己照片，审核员/管理员操作全部，观众不能访问候选接口。
- 搜索测试：口令门禁、精确 blind index、分页、空结果等价、限流、下载权限与标签更新。
- 隐私测试：数据库无号码明文，日志/URL/SSE 无搜索值，样本不进入 Git，图片不发往香港 OCR 服务。
- 性能测试：模型首次加载、缓存复用、WebGPU/WASM、OCR 与上传并行、移动端内存回落。

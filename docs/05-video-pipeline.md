# 视频处理与播放链路

状态：已批准的实施基线
更新日期：2026-08-26

## 1. 约束与目标

首版视频是“活动短片上传与播放”，不是直播推流或完整视频点播平台。由于禁止新增云端转码费用，兼容性和码率控制必须在上传者浏览器本地完成。

目标是得到一个可被微信、Safari、Chrome 和 Edge 直接播放的单码率 fast-start MP4，并通过 CDN Range 请求减少未观看部分的回源和下行浪费。

## 2. 输入与交付规格

| 项目 | 输入限制 | 平台交付规格 |
| --- | --- | --- |
| 容器 | MP4 | MP4，`moov` 位于媒体数据前 |
| 视频编码 | H.264/AVC | H.264/AVC，常见浏览器可解码 profile |
| 音频 | AAC 或无音轨 | AAC-LC 约 128kbps 或无音轨 |
| 时长 | 不超过 5 分钟 | 保持原时长 |
| 文件大小 | 不超过 500MB | 由目标码率决定，通常显著低于上限 |
| 分辨率 | 可高于 1080p | 最大 1920×1080 或 1080×1920，不放大 |
| 帧率 | 可高于 30fps | 最大 30fps |
| 视频码率 | 可高于目标 | 1080p 约 4Mbps；720p 及以下约 2Mbps |
| 云端保留 | 原文件只存在于用户设备 | 只保存合规/优化后的 MP4 |

输入不是 MP4、不是 H.264、存在不兼容音轨、超时长或超大小时直接拒绝。首版不尝试用 WebAssembly 软件编码任意视频格式。

## 3. 能力检测

上传页面懒加载媒体处理模块，避免增加观众端包体。选择视频后依次执行：

1. 使用 Mediabunny 流式读取容器和轨道信息。
2. 检查时长、大小、分辨率、帧率、视频/音频 codec 和 `moov` 位置。
3. 对需要重编码的视频调用 `VideoDecoder.isConfigSupported` 和 `VideoEncoder.isConfigSupported`。
4. 需要重编码音频时检查 `AudioEncoder`；AAC 已合规时优先复制音频 packet，避免无意义损失。
5. 设备不支持所需硬件/系统 codec 时停止，显示标准导出参数。

仅检测到全链路支持后才开始转码，不能处理到中途才发现没有输出编码器。

## 4. 本地处理路径

### 4.1 直接上传

同时满足 H.264/AAC、分辨率不超过 1080p、帧率不超过 30fps、平均视频码率不超过约 4Mbps 且为 fast-start 时，保留文件内容直接上传。

### 4.2 仅重封装

编码、分辨率、帧率和码率合规，但 `moov` 位于文件尾时，使用 Mediabunny 流式重封装为 fast-start MP4，不解码/重编码音视频。

### 4.3 自动转码

不满足画质规格但 codec 可被 WebCodecs 解码时：

1. 逐帧解码，按纵横比缩放至不超过 1080p。
2. 将帧率限制到 30fps；只丢弃多余时间点的帧，不改变播放速度。
3. 1080p 使用约 4Mbps，720p 及以下使用约 2Mbps；关键帧间隔目标 2 秒。
4. 通过硬件/系统 H.264 编码器输出。
5. AAC 合规时复制；不合规且 AAC 编码可用时转为约 128kbps，否则拒绝。
6. Mediabunny 流式封装为 fast-start MP4。

处理运行于专用 Worker。页面开启 Screen Wake Lock，并明确提示必须保持前台、电源充足和剩余磁盘空间。任务取消或失败后立即释放 VideoFrame、AudioData、编码器、临时输出和文件句柄。

## 5. 海报生成

- 从优化后视频的 `min(1 秒, 时长 10%)` 位置截取代表帧；极短视频使用首个可用非黑帧。
- 生成最长边 480、960 的 WebP，质量分别为 72 和 80。
- 保存视频实际宽高、时长和海报纵横比；不把海报正文发送到香港 API。
- 海报无法生成时视频不允许发布，避免观众列表自动加载 MP4 才能展示占位。

## 6. 对象命名与上传

固定路径：

- `media/albums/{albumId}/videos/{mediaId}/poster-480.webp`
- `media/albums/{albumId}/videos/{mediaId}/poster-960.webp`
- `media/albums/{albumId}/videos/{mediaId}/source.mp4`

两个海报使用普通预签名 PUT。视频使用 multipart，part 大小 16MiB；单个 500MB 视频最多约 32 个数据 part，加初始化和完成请求。

上传顺序为海报优先、视频随后。视频必须 CompleteMultipartUpload 成功并经 HEAD 校验大小、Content-Type 后才能进入 `ready`。与照片不同，视频不能仅凭海报进入公共直播。

IndexedDB 保存 upload ID、part ETag 和本地文件指纹。转码过程本身不做跨浏览器重启恢复；若转码完成后的本地文件句柄仍可访问，可以恢复上传分片，否则需要重新转码。

## 7. 不支持时的导出指引

上传页面必须展示工具无关的参数，而不是只给出“失败”：

- 容器：MP4；
- 视频：H.264；
- 最大分辨率：1080p；
- 帧率：30fps；
- 视频码率：约 4Mbps，720p 可用约 2Mbps；
- 音频：AAC-LC，约 128kbps；
- 启用“网络优化”“快速开始”或等价的 fast-start 选项；
- 时长不超过 5 分钟、文件不超过 500MB。

导出后的文件重新选择时创建新本地任务；已经失败且没有上传对象的意图可以取消清理。

## 8. CDN 与播放器

- `/media/.../videos/.../source.mp4` 使用长边缘缓存和 URL 鉴权。
- CDN 对视频路径开启固定 2MB Range 回源；OSS 必须正确返回 206、`Accept-Ranges` 和 `Content-Range`。
- 视频 object key 不覆盖，因此无需按版本刷新缓存。
- 播放器使用原生 HTML 视频能力，不引入播放器广告、统计 SDK 或 HLS 运行时。
- 初始列表只请求 WebP 海报；视频进入自动播放阈值前不设置实际媒体请求或保持 `preload=none`。

## 9. 可视自动播放

自动播放由全局协调器管理：

1. 媒体卡片至少 75% 进入视口，且页面已经完成主要内容绘制。
2. 候选中只选择视口中心最近的一条视频。
3. 设置静音、`playsInline` 后开始播放；同一时间最多一个实例。
4. 可见度低于 50%、切换标签页或另一视频成为候选时立即暂停。
5. 自动播放一遍后停在海报/末帧，不无限循环；用户可主动重播和开声音。
6. `Save-Data`、弱网、系统“减少动态效果”或浏览器拒绝自动播放时保持海报，用户点击才加载。

用户主动打开灯箱后显示原生控制条，可切换声音、暂停、拖动和全屏。关闭灯箱时停止播放并释放非必要缓冲引用。

## 10. 流量与质量验收

- 自动播放前只产生海报请求，不请求 MP4 正文。
- 首次 MP4 请求必须返回 206 或支持可验证的流式 200；拖动到未缓存位置时不得回源完整文件。
- 1080p 输出平均视频码率应位于目标值合理浮动范围，且不能因容器开销超过输入限制。
- 转码后的音画同步误差、方向、时长和关键帧跳转必须通过样片验证。
- 使用舞台暗光、快速运动、竖屏、静音、短片和接近 5 分钟的样片覆盖测试。
- 不用真实 CDN 做批量播放压测；压力验证使用本地 Range 源站，线上只做单文件小流量验收。

# 前端与交互设计

状态：已批准的实施基线；人脸找图为未来阶段，尚未实现
更新日期：2026-08-31

## 1. 设计语言

- 产品主名称：“中学部影像直播”。
- 默认浏览器标题：“北航实验学校中学部｜影像直播”。
- 风格：简洁、克制、以影像为主，不使用营销弹窗、滚动大动画或装饰性动态背景。
- 内部工作台固定使用浅色界面；公共相册默认跟随系统深色模式且首版不提供手动主题开关；照片灯箱固定使用深色背景。主题只改变页面界面，不改变照片本身。
- 字体使用系统字体栈，包括苹方、微软雅黑和通用 sans-serif，不请求第三方字体。
- 图标使用 `components.json` 固定的 Lucide 组件并打包为内联 SVG，不引用第三方 CDN。
- 管理员可配置团队展示名、Logo 和单一强调色；必须保证文字对比度。

### 1.1 视觉层级

- 公共相册以媒体为第一层，标题、状态、分类和搜索为第二层，品牌与分享为第三层；任何装饰不得与照片争夺首屏面积。
- 上传端以“当前能否继续上传”和“哪些文件需要处理”为第一层，速度、预计时间等诊断信息为第二层。
- 工作台以当前相册、待处理数量和高风险状态为第一层；统计不得挤占上传、审核、隐藏和删除等核心操作。
- 页面每个区域只保留一个主操作。并列次要操作使用普通或文字按钮，危险操作始终使用独立危险语义。

### 1.2 设计 Token

实现使用语义 CSS 变量作为唯一主题入口，业务组件不得直接依赖某个固定色阶。至少定义：

| Token | 用途 |
| --- | --- |
| `background` / `foreground` | 页面背景与正文 |
| `card` / `card-foreground` | 卡片、面板与浮层内容 |
| `popover` / `popover-foreground` | Select、Popover、菜单和悬浮内容 |
| `secondary` / `secondary-foreground` | 次要操作和低强调控件 |
| `accent` / `accent-foreground` | 悬停、键盘选择和当前菜单项 |
| `muted` / `muted-foreground` | 次级背景、说明和占位 |
| `border` / `input` | 分隔线、输入边框和禁用边界 |
| `primary` / `primary-foreground` | 主操作和当前选中状态 |
| `success/-foreground`、`warning/-foreground`、`destructive/-foreground` | 完成、风险和不可逆操作；不由品牌色覆盖 |
| `ring` | 键盘焦点和输入聚焦 |
| `overlay` | 抽屉、对话框和灯箱遮罩 |
| `sidebar-*` | 工作台侧栏表面、文字、强调、边框和焦点 |

未配置学校品牌色时使用以下默认值；shadcn/ui 生成器自带主题不得覆盖这张表：

| 模式 | `background` / `foreground` | `card` | `muted` / `muted-foreground` | `border` | `primary` / `primary-foreground` | `ring` |
| --- | --- | --- | --- | --- | --- | --- |
| 工作台/公共浅色 | `#FFFFFF` / `#0F172A` | `#FFFFFF` | `#F1F5F9` / `#475569` | `#CBD5E1` | `#1D4ED8` / `#FFFFFF` | `#2563EB` |
| 公共深色/灯箱 | `#0B1120` / `#F8FAFC` | `#111827` | `#1E293B` / `#CBD5E1` | `#475569` | `#60A5FA` / `#0F172A` | `#93C5FD` |

shadcn 结构 Token 固定如下：

| 模式 | `popover` / foreground | `secondary` / foreground | `accent` / foreground | `input` | `sidebar` / foreground / accent |
| --- | --- | --- | --- | --- | --- |
| 工作台/公共浅色 | `#FFFFFF` / `#0F172A` | `#F1F5F9` / `#0F172A` | `#E2E8F0` / `#0F172A` | `#CBD5E1` | `#F8FAFC` / `#0F172A` / `#E2E8F0` |
| 公共深色/灯箱 | `#111827` / `#F8FAFC` | `#1E293B` / `#F8FAFC` | `#334155` / `#F8FAFC` | `#475569` | `#111827` / `#F8FAFC` / `#334155` |

`sidebar-primary/-foreground`、`sidebar-border` 和 `sidebar-ring` 分别复用当前模式的 `primary/-foreground`、`border` 和 `ring`。`--radius` 基准为 `12px`，组件尺寸 variant 派生较小控件圆角，不在页面另设不一致圆角。

- 默认浅色主操作悬停/按下分别使用 `#1E40AF` / `#1E3A8A`；公共深色分别使用 `#93C5FD` / `#BFDBFE`，前景保持深色。
- 浅色固定状态色/前景为成功 `#166534/#FFFFFF`、警告 `#854D0E/#FFFFFF`、危险 `#B91C1C/#FFFFFF`；深色为成功 `#4ADE80/#052E16`、警告 `#FACC15/#422006`、危险 `#F87171/#450A0A`。低强调 badge 可以降低背景色强度，但文字/图标与背景仍需独立满足对比度。
- 管理员提供的强调色只作为 `primary` 候选，不改变成功、警告或危险语义。
- 表中十六进制值是规范化颜色参考；Tailwind/shadcn/ui 实现将其转换为等价 OKLCH CSS 变量。组件只使用 `bg-primary`、`text-muted-foreground` 等语义类，不在组件中重复原始色值或手写 `dark:` 颜色分支。
- 系统在候选色上从浅色和深色前景中选择对比度更高者，并对默认、悬停、按下和焦点状态分别校验；任一关键状态达不到 WCAG AA 时使用默认蓝色，不保存一个视觉上可选但实际不可用的组合。
- 字号使用 `12/14/16/20/24/32px` 六级，正文默认 `16px`，后台高密度辅助信息最低 `12px`；正文行高不低于字号的 1.5 倍。
- 间距以 `4px` 为基础单位，常用阶梯为 `4/8/12/16/24/32/48/64px`。控件圆角 `8px`，卡片和对话框 `12px`，状态 chip 使用胶囊圆角。
- 阴影只用于悬浮菜单、粘性工具栏、抽屉、对话框和灯箱；普通媒体卡片依靠间距与边框分组。
- 动效默认 `120–200ms`，只表达出现、消失、展开和位置关系。启用减少动态效果时移除平滑滚动、缩放和大位移动画。

### 1.3 组件基础

UI 基础遵循 [ADR-009](adr/009-lightweight-owned-ui-foundation.md)及其[ADR-010 修订](adr/010-base-ui-and-shadcn-governance.md)：Tailwind CSS 提供 Token 和布局，shadcn/ui 生成项目可拥有的组件源码，交互原语使用 Base UI，视觉结构固定为 `base-nova`。只按实际页面需要纳入 `Button`、`FieldGroup/Field/FieldSet`、输入控件、`InputGroup`、`ToggleGroup`、`Dialog`、`AlertDialog`、`Drawer/Sheet`、`Tabs`、`Sidebar`、`Breadcrumb`、`Select`、`Checkbox`、`DropdownMenu`、`Popover`、`Tooltip`、`Toast`、`Alert`、`Card`、`Badge`、`Avatar`、`Progress`、`Skeleton`、`Spinner`、`Empty`、`Separator` 和表格基础，不一次性安装整个组件目录。

公共相册不直接套用后台模板；它复用 Token、按钮、对话框和可访问原语，但媒体网格、实时提示、灯箱内容和下载交互保持产品定制。表单使用 React Hook Form 并复用 Zod 契约；服务端仍是权限与数据合法性的最终判断者。

- 表单布局使用 `FieldGroup` + `Field`，关联选择使用 `FieldSet` + `FieldLegend`；字段错误同时设置字段容器 `data-invalid` 与控件 `aria-invalid`，禁用同时设置容器 `data-disabled` 与控件 `disabled`。
- 输入内图标、单位、计数或操作使用 `InputGroup` + `InputGroupInput/InputGroupTextarea` + `InputGroupAddon`；输入内按钮使用 `InputGroupButton`，不以绝对定位把普通 Button 叠在 Input 上。
- 两到五个互斥/多选模式使用 `ToggleGroup`，包括观众“按号码/按年级班级”切换；不循环渲染带手工选中样式的 Button。
- 状态使用 `Badge` 或语义状态 Token，说明/警告使用 `Alert`，空状态和骨架分别使用 `Empty` 与 `Skeleton`，分隔使用 `Separator`。
- Base UI 基座的瞬时通知固定使用 shadcn `Toast`。通知只补充结果，不能替代页面错误摘要、字段错误或不可逆操作确认。
- `Dialog`、`AlertDialog`、`Sheet` 和 `Drawer` 必须包含可访问标题；危险操作使用 `AlertDialog`，移动端底部任务面板使用 `Drawer`，桌面筛选/详情侧栏使用 `Sheet`。
- 优先使用组件内置 variant；`className` 只承担布局，不覆盖组件颜色和字体。Overlay 使用组件层级，不添加任意 `z-index`。

### 1.4 shadcn 组合规则

- Base UI trigger/close 组合使用 `render`，不使用 Radix `asChild`，也不增加无语义包装元素。`render` 输出链接等非原生 Button 时按当前组件 API 设置 `nativeButton=false`。
- `SelectItem/SelectLabel`、`DropdownMenuItem/Label/Sub` 和 `CommandItem` 分别放入 `SelectGroup`、`DropdownMenuGroup` 和 `CommandGroup`。Base Select 的 `items`、placeholder、multiple 和对象值完全按当前 Base 文档使用，不复制 Radix 示例。
- 后台面板使用完整 `CardHeader`、`CardTitle`、`CardDescription`、`CardAction`、`CardContent`、`CardFooter` 结构；公共媒体缩略卡是产品专用链接/按钮，不为套 Card 而增加无意义层级。
- `TabsTrigger` 必须位于 `TabsList`；`Avatar` 必须提供 `AvatarFallback`；加载按钮使用 `Spinner` + `data-icon` + `disabled`，不创造 `isLoading`/`isPending` 私有 Button API。
- Lucide 图标通过组件对象传递，不使用字符串到图标的全局映射。Button 内图标设置 `data-icon="inline-start|inline-end"`，不添加组件已管理的 `size-*` 或边距类。
- Tailwind 布局使用 `gap-*`，不使用 `space-x-*`/`space-y-*`；等宽高元素使用 `size-*`；单行省略使用 `truncate`；条件类使用项目 `cn()`，不在模板字符串中维护颜色状态。
- `apps/web/src/app/globals.css` 为唯一主题 CSS 入口；应用根容器设置 `isolation: isolate`，`body` 设置 `position: relative`，保证 Base UI portal 与 Drawer 在 iOS 滚动后正确覆盖视口。页面不以任意 `z-index` 修补 portal 层级。
- 加载占位使用 `Skeleton`，文本闪烁/滚动边缘只使用已纳入基础样式的 `shimmer`/`scroll-fade` 工具，不在页面编写重复 keyframes 或渐变 mask。
- 共享组件优先使用内置 variant，其次语义 Token，再考虑在组件源码中增加可复用 variant。页面不得复制 shadcn 组件样式到临时 `div`。
- 在编写任何通用组件前先搜索官方组件及明确选择的社区候选；通用媒体网格、上传队列和 OCR 覆盖层只有在现有组件不能表达产品行为时才自定义，并复用现有 Button、Badge、Progress、Dialog 等原语。

### 1.5 响应式几何

| 视口 | 页面留白 | 公共媒体网格 | 内部导航 |
| --- | --- | --- | --- |
| `<480px` | 左右 `12px` | 2 列、`8px` 间距 | 顶栏 + 抽屉 |
| `480–767px` | 左右 `16px` | 3 列、`8px` 间距 | 顶栏 + 抽屉 |
| `768–1023px` | 左右 `24px` | 4 列、`12px` 间距 | `72px` 折叠侧栏 |
| `>=1024px` | 左右至少 `24px` | `minmax(176px, 1fr)` 自动增列、`12px` 间距，内容最大 `1440px` | `240px` 侧栏；窗口不足时折叠 |

- 上传端在 `<1024px` 使用单列队列；`>=1024px` 使用主队列加 `320px` 任务摘要栏。
- 工作台主内容最大宽度 `1600px`。表单正文最大宽度 `960px`，避免超宽输入行；审核网格和媒体管理可以使用全部可用宽度。
- 手机底部操作条和灯箱控制必须考虑 `safe-area-inset-*`。任何核心操作不得只通过悬停出现。
- 公共端和上传端主要触摸目标不小于 `44×44 CSS px`；桌面高密度控件不得小于 `32px`，且在触摸视口恢复到 `44px`。

## 2. 路由结构

### 2.1 三类界面壳

- `PublicGalleryShell` 服务 `/g/{slug}`：只有紧凑品牌区、相册上下文、分类/搜索和媒体内容，不出现内部导航。
- `UploadShell` 服务相册上传路由：持续显示相册、网络和队列状态；手机使用底部队列总控，桌面显示任务摘要栏。
- `StudioShell` 服务其他 `/studio` 路由：桌面使用侧栏，手机使用抽屉；当前路由、相册上下文和页面标题始终可见。

界面壳只是前端布局边界，不改变会话、角色或 API。导航隐藏用户无权访问的入口，但服务端仍必须独立拒绝越权请求。

### 2.2 路由表

| 路由 | 目标用户 | 内容 |
| --- | --- | --- |
| `/g/{slug}` | 观众 | 相册口令、封面、直播流和灯箱 |
| `/login` | 内部人员 | 登录与首次改密 |
| `/offline` | 上传者 | 断网时的只读离线说明壳 |
| `/studio` | 内部人员 | 活动总览 |
| `/studio/albums/{id}` | 管理员/审核员 | 相册配置、媒体管理和统计 |
| `/studio/albums/{id}/upload` | 上传者 | PWA 上传队列 |
| `/studio/albums/{id}/review` | 管理员/审核员 | 待审核与批量操作 |
| `/studio/users` | 管理员 | 成员与角色 |
| `/studio/audit` | 管理员 | 审计记录 |

内部页面在手机与桌面均可使用，但批量审核以平板/桌面效率优先。观众页面以微信手机视口优先。

### 2.3 导航规则

- 工作台一级导航固定为“活动”；管理员另外看到“成员”和“审计”。上传者和审核员不看到无权限入口。
- 相册上下文导航固定为“概览/媒体”“上传”“审核”“设置/统计”四组，并根据角色隐藏整组；基础路由继续使用上表，不为了纯视觉标签增加 API。
- 手机子页面顶栏提供明确返回目标，不能依赖浏览器手势。桌面使用面包屑表达“活动 > 当前相册 > 当前任务”。
- 未保存表单离开、活动上传中离开和永久删除使用不同拦截文案；普通只读页面不弹离开确认。
- 会话过期后保存当前安全路由和非敏感表单草稿。重新登录成功只回到原站内路由，不接受任意外部返回地址。
- Next.js 路由分别提供加载、段级错误、全局错误、未找到、未登录和无权限页面，并复用本章 Token/状态组件；公共口令页仍不区分相册不存在与无权访问，不能因框架错误页泄露内部差异。

## 3. 观众相册

### 3.1 口令入口

- 页面先显示学校品牌、相册标题和口令输入，不预请求任何媒体列表。
- 错误提示不区分“相册不存在”和“无权访问”的内部细节。
- 连续错误触发短时等待，避免暴力枚举。
- 解锁后建立 HttpOnly 访客会话；前端不保存相册口令。

### 3.2 相册头部

头部包括封面、标题、说明、活动时间、直播状态、分享按钮、分类栏，以及启用时的号码/人脸找照片入口。移动端首屏不得被超高封面占满；封面采用固定最大高度并保留相册标题可见。

分类栏在滚动后可吸顶。切换分类使用独立游标并取消旧请求，不能混入前一个分类结果。

### 3.3 规整网格

- 手机两列、较宽手机/小平板三列、桌面根据宽度增加列数。
- 卡片使用固定方形视觉框，照片以 `object-fit: cover` 裁切；灯箱显示完整比例。
- 服务端只提供纵横比，卡片使用中性骨架背景提前保留空间，避免 CLS；不传输主色或模糊图占位数据。
- 初始服务器渲染 30 条，但只让接近视口的照片触发下载。
- 超过约 200 个挂载卡片后启用窗口化/虚拟化，保持滚动稳定。

### 3.4 新媒体行为

- 用户位于顶部附近时，新媒体平滑插入并更新计数。
- 用户已向下浏览时，内容不移动；顶部显示“有 N 条新影像”浮动按钮。
- 点击按钮滚动至顶部、合并增量并保持发布序号顺序。
- 同一媒体的 1920/原图完成只更新能力，不显示为“新影像”。

### 3.5 灯箱

- 照片完整适配视口，不裁切；支持上一张、下一张、关闭、分类与下载状态。
- 只预取当前相邻一张 1920；省流量模式不预取。
- 键盘支持 Escape、左右方向键；触摸支持横向切换，但纵向页面滚动与下拉关闭不能冲突。
- 焦点进入灯箱后被约束在对话框内，关闭后回到原卡片。

### 3.6 下载

相册分别控制普通图和照片原图下载。下载按钮先调用香港 API 校验当前会话与开关，再跳转到 5 分钟 CDN 地址。按钮文案必须标明文件类型和预计大小；原图未完整时不显示按钮。开启照片原图下载时必须提示原文件可能仍含拍摄时间、相机信息或 GPS 等 EXIF 元数据。

### 3.7 号码找照片

- 只在口令相册明确启用 `bibSearchEnabled` 时显示。
- 提供互斥的“按号码”和“按年级班级”模式；切换模式清除另一模式的条件。
- 输入框根据号码规则显示位数示例，但不提供号码列表、自动补全、最近搜索或相近号码。
- 搜索使用 POST，号码只保存在当前页面内存；刷新后不自动恢复。
- 结果只包含人工确认且已发布的照片，继续使用规整网格、灯箱和下载权限。
- 属性模式先选择年级，再显示该年级下配置的班级；可以只选年级，不允许单独选班级。
- 年级+班级必须来自照片中同一个确认号码标签；属性不默认显示在照片卡片或灯箱上。
- 无号码照片仍出现在普通相册流，但不出现在号码、年级或班级筛选结果。
- 无匹配、匹配照片未发布和号码不存在使用同一空状态，避免旁路枚举。
- 搜索期间收到通用号码更新事件时静默重新查询，不在通知中展示号码。

### 3.8 人脸候选找图（未来）

- 只在已解锁口令相册明确启用且索引可用时显示“上传照片找我”入口；公开相册、索引删除中或授权门禁未完成时不显示。
- 打开后先显示独立同意对话框：说明学校/处理者、阿里云 IMM、处理目的和方式、参考照最长 1 小时、结果最长 2 小时、可能漏检/误判及投诉联系人。未勾选“本人”或“监护人/已获授权”声明不得选择照片。
- 一次只选择一张 JPEG/PNG/WebP；HEIC/HEIF 仅在当前浏览器能原生解码时接受，否则提示改选兼容格式，不上传云端转换。选择后先显示本地预览与“仅允许清晰单人照”说明；重新选择会释放旧 Blob/Object URL，不持久化到 IndexedDB、Cache Storage 或历史记录。
- 同意对话框明确提示：共享相册口令和声明不是身份核验，用户不得提交未获授权人物照片。
- 处理状态依次为“正在安全处理参考照”“正在查找候选”“已显示初步结果，正在补查”“已完成”。同步聚类结果可先显示，异步结果只追加新媒体，不打乱当前灯箱或滚动位置。
- 零脸、多脸、低质量、供应商失败和限流分别给出具体下一步；不存在匹配、匹配均未发布和输入人物不在相册使用同一空状态。
- 结果标题固定为“可能包含此人的照片”，不显示相似度、人物名称、聚类或“已识别本人”等确定性语言。结果复用普通网格、灯箱和下载权限。
- 提供“清除本次结果”操作，清除页面内存并请求取消/清理；它不是参与者授权撤回入口。授权投诉继续使用页脚联系人处理。
- 页面离开或会话过期后不恢复参考照；后台任务仍按服务端期限清理，重新进入需再次同意和提交。

## 4. 上传 PWA

### 4.1 文件选择

- 桌面支持多选和目录选择；手机支持系统文件/相册选择。
- 明确提示上传端应使用系统 Chrome、Edge 或 Safari，不支持微信内上传。
- 选择后立即进行格式、大小和数量预检，失败项不进入处理队列。
- 上传前选择一级分类，后续仍可在审核页批量修改。
- 相册启用号码识别时，页面在用户确认后懒加载自托管 OCR 模型；模型未准备好不阻止选择和上传照片。

### 4.2 队列卡片

每个文件显示本地缩略图、文件类型、当前阶段、总进度、传输速度、剩余估计和具体错误。阶段至少区分：等待、本地处理、上传预览、等待审核/已发布、上传完整文件、完成、失败、取消。号码识别另有独立状态：等待 OCR、识别中、待复核、有确认号码、确认无号码、需复核、识别失败。

不能用单一“100%”掩盖原图仍未上传。照片预览发布后继续显示“直播已可见，原图上传中”。

OCR 候选使用号码 chip 和可切换的框覆盖层展示。上传者可确认、修正、拒绝或手工添加；确认后立即显示自动派生的年级/班级。置信度必须以文字辅助表达，不能只用颜色。

OCR 无结果/失败或全部候选被拒绝时仍显示“待复核”，并并列提供“手工添加号码”和“确认无号码”两个动作；系统不能把无候选显示成“确认无号码”。确认无号码后显示明确徽标和“撤销”入口。

### 4.3 控制与恢复

- 支持暂停整个队列、恢复、取消单项、重试失败项和清除已完成项。
- 页面存在活动任务时拦截误关闭并给出真实限制：浏览器被系统关闭后不会继续后台上传。
- 网络恢复后先查询服务端状态，再续传；不盲目重发已完成对象。
- 移动端内存不足时降低处理并发而不是降低输出规格或静默跳过。
- OCR 只允许一个 Worker 任务并发，模型下载、推理和照片上传进度分开展示；规则版本失效时提示刷新规则而不是重复上传照片。

### 4.4 上传布局与状态轴

队列卡片不得把多个领域状态压缩成单一枚举。界面同时展示：

| 状态轴 | 来源 | 用户可见表达 |
| --- | --- | --- |
| 媒体处理/上传 | `IngestStatus` | 等待、本地处理、上传预览、上传完整文件、完成、失败、取消 |
| 发布 | `PublicationStatus` | 待审核、已发布、已隐藏；上传者无权改变时只读 |
| 号码候选 | `BibTagStatus` | OCR 候选、已确认候选、已拒绝、需复核；可以有多条 |
| 照片号码复核 | `BibReviewDecision` | 待复核、有确认号码、确认无号码、需复核 |

`BibTagStatus` 说明单条标签，`BibReviewDecision` 说明整张照片是否完成有无号码判断；界面不得用“已确认”同时代表二者。

手机：

```text
┌ 返回  相册名称       网络状态 ┐
├ 选择照片       选择分类       ┤
├ 队列摘要：处理中/失败/待复核   ┤
│ [缩略图] 文件一               │
│  上传状态  发布状态  号码状态   │
│  进度、速度、错误与单项操作     │
│ [缩略图] 文件二 …             │
└ 暂停全部   重试失败   清理完成 ┘  <- 安全区内固定
```

桌面在右侧固定任务摘要栏，展示并发、网络、存储恢复、OCR 模型和队列总控；文件卡片仍是主内容，摘要栏不重复全部单项操作。

## 5. 内部工作台

### 5.1 活动总览

以状态分组显示草稿、直播中、已结束和归档活动。卡片展示媒体数量、待审核数量、不完整上传、最近更新时间和访问模式。

### 5.2 相册设置

使用分区表单：基本信息、访问、发布、下载、号码规则与年级班级映射、未来人脸找图、分类和品牌。高风险更改明确显示影响：

- 改口令会让已解锁观众退出；
- 从口令改公开会让任何获得链接者访问；
- 开启下载会增加二次传播与 CDN 流量；
- 结束直播会停止实时更新但保留相册浏览。
- 开启号码搜索会把确认号码用于照片检索，并强制相册保持口令访问；
- 修改号码规则会重新校验标签，不符合新规则的标签立即退出搜索并进入复核。
- 修改年级/班级映射会从确认号码重算属性，重算期间观众属性筛选暂时关闭。
- 开启人脸找图要求口令模式、当前告知版本、参与者授权核验、影响评估和投诉联系人；会建立新的阿里云处理与费用边界。
- 关闭人脸找图或改为公开相册会立即停止观众搜索并进入“删除索引中”；完成前不得显示为已彻底删除。

号码规则编辑器使用卡片式模式和数字槽位预览：管理员配置总位数、约束起始位/宽度及一个或多个允许区间。未约束位置显示“任意”，提供测试号码和逐条件结果，不暴露正则表达式。

映射编辑器提供“年级”和“班级”两个维度，管理员先维护有序显示选项，再配置指定位置/区间到选项的映射。例如第 1 位 `1 → 初一`，第 2–3 位 `01 → 一班`。测试号码必须同时展示合法性、年级和班级，冲突映射不能启用。

人脸设置只展示功能开关、告知版本、授权核验时间、索引覆盖/失败/排除数量、最近聚类时间、30 天删除期限和通用失败码；不得展示人物分组、供应商额外属性、相似度或人脸框。支持重试失败任务、让选中照片退出索引和删除整册索引，危险操作需要近期认证和二次确认。

### 5.3 审核

审核页以高密度网格展示待审核内容，支持单选、范围选择、全选当前筛选结果、批量发布/隐藏/改分类。批量结果逐项展示，不能将部分失败显示成整体成功。

启用号码识别时，审核卡片显示候选 chip、框和号码派生的年级/班级。审核员可以发布时顺手确认，但发布按钮不等待 OCR；支持筛选待复核、有确认号码、确认无号码、识别失败、需复核、年级和班级，并支持给选中照片手工添加同一号码或批量确认无号码。旧照片只通过手工入口补录，不提供自动补扫按钮。

“无号码”与确认号码互斥：有确认号码时必须先删除号码才能标记无号码；后续手工添加号码会自动撤销无号码；删除最后一个号码只恢复待复核，不自动标记无号码。

### 5.4 永久删除

默认操作是隐藏。永久删除需要管理员、二次确认和输入相册标题/明确确认词；界面说明将删除 OSS 对象并刷新 CDN，完成后不可恢复。

### 5.5 工作台布局契约

桌面：

```text
┌ 侧栏 240px ┬ 页面标题、面包屑                 账号 ┐
│ 活动        ├ 相册标题、状态与关键计数              ┤
│ 成员*       ├ 概览/媒体  上传  审核  设置/统计       ┤
│ 审计*       ├ 筛选、批量操作与选择摘要              ┤
│             │ 主内容：网格、表单或表格              │
```

## 6. 统一界面状态、实时与网络降级

### 6.1 页面状态矩阵

每个数据区域必须实现下列状态，不允许让空白页面同时表示加载、无数据和失败：

| 状态 | 界面要求 | 恢复与焦点 |
| --- | --- | --- |
| 首次加载 | 保留最终布局尺寸的骨架；口令页除外 | 完成后不抢走用户当前焦点 |
| 空状态 | 说明为何为空；有权限时提供一个主操作 | 主操作使用真实下一步，不提供无效刷新 |
| 离线/陈旧数据 | 明确“离线，显示上次内容”和最后更新时间 | 网络恢复后静默刷新，冲突时再提示 |
| 可重试错误 | 说明失败对象与是否保留进度 | 焦点移到错误摘要，提供局部重试 |
| 不可重试错误 | 说明限制和人工下一步 | 不显示会重复失败的重试按钮 |
| 会话过期 | 暂停需签名/API 的操作，保留 IndexedDB 队列 | 登录后先查询服务端状态再续传 |
| 权限变化 | 立即撤销相应编辑/批量操作 | 保留本地文件但不绕过服务端；提示联系管理员 |
| 部分成功 | 逐项显示成功与失败，不用单一成功 Toast | 焦点进入结果摘要，可筛选失败项 |
| 后台任务进行中 | 展示任务对象、阶段和可否离开 | 重进页面从服务端状态恢复，不假装浏览器后台常驻 |
| 人脸初步结果 | 明确仍在异步补查并只追加候选 | 用户可继续浏览；失败不清空已验证的初步结果 |

### 6.2 实时与网络降级

- SSE 连接状态在观众端低调展示，在后台明确展示。
- SSE 中断不弹连续错误；切换到 15 秒轮询并在恢复后补齐游标。
- 离线时观众可继续查看浏览器已有缓存，但不承诺完整离线相册。
- 受口令保护的 API 响应设置 `no-store`，Service Worker 不缓存 API、相册、工作台页面或 OCR 资源。
- 上传页注册最小 Service Worker，只缓存离线说明页和同源哈希构建资源；受保护导航断网时显示离线壳，实际登录、读取任务权威状态和上传仍需要网络。任务元数据继续只保存在 IndexedDB。

## 8. 无障碍与文案

- 目标为 WCAG 2.2 AA；正文和操作控件达到对应对比度目标。
- 所有按钮有可访问名称，状态不只依赖颜色。
- 支持键盘操作、焦点可见、减少动态效果和触摸目标最小尺寸。
- 照片没有人工说明时使用中性替代文本，不根据人物作自动推断。
- 人脸结果使用“可能包含”并提供准确率限制；屏幕阅读器只播报任务阶段和新增结果数量，不播报相似度或推断身份。
- 错误文案说明“发生什么、是否可重试、用户下一步做什么”，不展示技术堆栈。
- 页面提供跳到主要内容的链接，并使用 `header`、`nav`、`main`、`aside` 和 `footer` 地标；标题层级不得因视觉字号跳级。
- 上传进度、批量结果和新媒体数量使用节流后的 live region；不逐百分比播报，也不在 SSE 心跳时打断屏幕阅读器。
- 所有拖拽、框选、滑动和长按操作必须有按钮或键盘等价路径。批量范围选择不能只依赖 Shift+鼠标。
- 对话框打开后焦点进入标题或首个合理控件，关闭后回到触发元素；危险确认默认聚焦取消动作。
- Toast 只补充结果，不能成为错误、权限变化或不可逆操作的唯一载体。

## 9. 性能预算

- 初始 JS/CSS gzip 后不超过 300KB。
- 暖缓存 Fast 4G 下公共页 p75 LCP 目标不超过 2.5 秒、INP 不超过 200ms、CLS 不超过 0.1，移动与桌面分别记录。
- 首屏媒体目标不超过约 1.2MB；不自动下载照片原图。
- 页面滚动时避免同步布局读取或一次挂载全部 5,000 项。
- OCR 模型/Worker 不进入观众端包体，仅在启用功能的内部页面懒加载；压缩总量预算不超过 35MB并缓存一年。
- 公共相册以 Server Component 输出静态结构和首批 30 条；分类、号码/人脸搜索、SSE 增量和灯箱分别形成最小 Client Island，不把整个页面标记为客户端组件。
- Server Component 只向 Client Island 传可序列化的 API 表示；浏览器专用组件不得声明为异步 Client Component，也不得把 `window`、IndexedDB 或 Worker 依赖导入服务端图。
- 主站逐请求生成 CSP nonce，因此页面使用动态渲染；不得为恢复静态预渲染而放宽脚本 CSP。该取舍的 2C2G 运行成本必须在阶段 5/试运行测量。
- 灯箱、Embla、长列表虚拟化和 OCR 按路由或首次操作动态加载。未来人脸找图 UI 也只在点击入口后加载，并复用现有照片处理原语；观众包体不得包含 OCR 或人脸模型。shadcn/ui 组件逐项引入，不允许以便利为由纳入未使用组件。
- 包体报告按公共相册、上传端和工作台分别记录；工作台组件不得计入公共相册初始路由，公共相册通过预算不能掩盖上传端意外加载 OCR 代码。

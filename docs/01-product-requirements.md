# 产品需求

状态：已批准的实施基线；人脸找图已本地实现，生产启用仍待独立验收
更新日期：2026-09-02

## 1. 产品定义

平台名称为“中学部影像直播”，浏览器标题可使用“北航实验学校中学部｜影像直播”。平台用于校内活动照片的快速采集、审核、发布与受控观看，不面向社会经营，也不是公开图片社区。产品只接受照片，不为其他媒体类型保留上传、处理、播放、下载或未来实现占位。

产品首版必须形成以下完整闭环：

1. 管理员创建活动相册并设置访问、分类和发布方式。
2. 摄影人员从手机或电脑系统浏览器选择本地照片。
3. 浏览器在本地处理照片并直接上传北京 OSS；启用号码识别时同步生成数字候选。
4. 自动发布相册直接进入观众端；审核相册进入待审核区，号码确认不阻塞发布。
5. 观众通过分享链接或二维码输入相册口令并实时看到新内容，可在已启用相册中输入号码筛选照片。
6. 管理员按相册决定是否允许普通图或照片原图下载。

经 [ADR-012](adr/012-consent-gated-face-photo-search.md) 批准的人脸候选找图是上述闭环之后的独立可选阶段，不阻塞现有照片、号码牌或试运行功能，也不因文档批准自动获得编码或云端开通授权。

## 2. 用户与权限

| 角色 | 主要能力 | 明确限制 |
| --- | --- | --- |
| 管理员 | 成员、相册、品牌、访问/下载/号码及年级班级规则、人脸索引、内容和审计管理 | 不能查看用户密码明文、CDN 鉴权密钥、人脸向量或供应商额外属性 |
| 审核员 | 查看待审核媒体、批量发布、隐藏、调整分类、确认号码/无号码 | 不能管理成员、云端配置或永久删除相册 |
| 上传者 | 查看获授权相册、上传并重试任务、确认自己照片的号码/无号码 | 不能发布审核相册、修改访问策略或操作他人内容 |
| 观众 | 经口令或公开链接浏览、按权限下载；口令相册可精确搜号码，未来可在启用相册提交一张参考照找候选照片 | 无后台账号、不能上传相册媒体、查看号码/人物目录、评论、公开发布或跨相册搜索 |

管理员通过服务器侧初始化命令创建首个账号。后续账号由管理员创建，使用临时密码首次登录并强制修改。首版不接入短信、微信 OAuth、邮件找回或第三方身份系统。

## 3. 相册模型与默认值

每个相册包含标题、说明、封面、活动时间、状态、一级分类、发布模式、访问模式、下载策略、号码规则、人脸找图配置、品牌展示和排序信息。

默认值固定如下：

- 状态：草稿；
- 访问：随机生成至少 8 位的相册口令；
- 发布：先审核后发布；
- 普通图下载：关闭；
- 照片原图下载：关闭；
- 水印：第一版不提供；
- 号码识别与观众号码搜索：关闭；
- 人脸候选找图：关闭；
- 分类：可选一级分类，默认提供“全部”；
- 内容排序：按服务端分配的发布序号倒序，发布时间相同时仍保持稳定顺序。

管理员可以将明确获得授权的活动改成公开链接、自动发布或允许下载。改变相册口令时，已有观众会话立即失效。人脸找图只能在口令相册中逐项启用；改为公开访问会立即停止人脸搜索并启动索引删除，改回口令也不会自动恢复。

## 4. 照片需求

- 接受 JPEG、PNG、WebP；单文件最大 50MB、最大 100MP。
- 上传者浏览器本地生成 480、960、1920 三档派生图；第一版优先 WebP。
- 480 和 960 派生图成功后即可进入发布或审核流程，1920 和原图继续后台上传。
- 原图未完成时，观众端不得出现原图下载入口。
- 公开派生图不得包含 EXIF、GPS、原始文件名或其他相机私密信息；原图在 OSS 中保持原始内容。
- 相册内支持一级分类、批量审核、批量隐藏和按上传者筛选。

详细规格见[照片处理与上传链路](04-photo-pipeline.md)。

## 5. 号码牌识别需求

- 号码牌管线只识别照片中的印刷阿拉伯数字，不识别人脸、姓名、手写或球服号码；未来人脸找图使用完全独立的开关、供应商和数据流。
- 相册可配置多个结构化数字模式；每个模式可限制总位数及任意连续位置的允许区间，未限制位置允许任意数字。
- 相册可配置号码到年级、班级的确定性位置映射，例如第 1 位 `1 → 初一`、第 2–3 位 `01 → 一班`。
- PaddleOCR.js 在上传者浏览器本地生成号码候选，照片和 OCR 图片不发送香港或第三方服务。
- OCR 候选必须由上传者、审核员或管理员确认后才进入搜索；照片发布不等待确认。
- 号码确认/修改后自动重算该号码的年级和班级属性；多号码照片分别保留每个号码的属性。
- 一张照片可以关联多个确认号码；历史照片首版只支持手工补录。
- OCR 无候选、失败或全部候选被拒绝都保持待复核；“无号码”只能由人工明确确认，并与确认号码互斥。
- 观众号码搜索只允许口令相册精确查询，不提供号码列表、自动补全、模糊搜索或跨相册搜索。
- 观众可只按年级或按“年级 + 班级”筛选；年级和班级必须来自同一个确认号码，无号码照片只保留在普通相册流。
- 号码按可能关联未成年人身份的数据保护，数据库加密保存并使用相册作用域 blind index 搜索。

详细规格见[号码牌识别与筛选](12-bib-recognition.md)。

## 6. 人脸候选找图（独立门禁阶段）

- 学校必须先完成参与者单独同意、未满十四周岁监护人同意、个人信息保护影响评估和投诉处理流程，并确认被索引照片内全部可识别人脸在授权范围；管理员只可在符合条件的口令相册中启用。
- 只把已发布且 1920 派生图完整的照片索引到同地域阿里云 IMM；每个相册使用独立 Dataset，不建立姓名、学号、号码或花名册映射。
- 观众每次明确同意后提交一张本人或已获授权人物的清晰单人照。浏览器去 EXIF 后直传北京临时私有 OSS；参考照正文不经过香港。
- 聚类分页结果与 EventBridge 异步相似补查合并后，再以 PostgreSQL 权威状态过滤到当前相册的已发布照片。
- 结果文案固定为“可能包含此人的照片”，高精度优先；低清、遮挡、侧脸、年龄跨度和极少出现的人物可能漏检。
- PhotoStream 不保存人脸向量；年龄、性别、情绪、吸引力等供应商额外属性直接丢弃，不进入数据库、日志、备份、API 或 UI。
- 参考照正常完成即删除、最长 1 小时，短期结果最长 2 小时；相册结束 30 天后删除整册人脸索引。
- 只允许同相册搜索，不提供人物列表、姓名标注、跨相册追踪、实名核身或将人脸结果用于发布审核。

详细规格见[人脸候选找图](14-face-search.md)。

## 7. 观众体验

观众端以手机和微信内浏览为第一优先级，同时支持当前 Chrome、Edge、Safari。页面包括：

- 学校/中学部品牌、相册标题、活动说明和封面；
- 直播中、已结束等清晰状态；
- 一级分类筛选；
- 已启用口令相册的精确号码找照片入口；
- 已启用口令相册的年级与班级级联筛选；
- 已启用口令相册的人脸候选找图入口、单独同意、参考照选择、处理进度和短期结果；
- 照片规整网格；
- 新内容提示，不在观众阅读旧内容时强制跳动；
- 支持键盘、触摸和手势的照片灯箱；
- 相册分享、链接复制和二维码；
- 由相册策略决定的下载按钮；
- 隐私说明与删除/投诉联系方式。

## 8. 内部工作台

内部工作台包括：

- 账号登录、首次改密和退出；
- 活动列表、创建、编辑、开始、结束和归档；
- 上传队列、网络状态、本地派生进度、暂停、取消、重试和重新选择文件；
- 号码 OCR 状态、候选框、确认/改正/拒绝、手工补录、“无号码”、年级/班级映射和规则测试；
- 人脸找图启用门禁、索引进度/失败、媒体退出索引、整册删除和 30 天保留状态；
- 待审核、已发布、上传不完整、失败和隐藏内容视图；
- 分类、上传者和状态筛选；
- 批量发布、隐藏、恢复和永久删除；
- 成员与角色管理；
- 匿名浏览量、下载链接签发量和媒体存储量概览；
- 关键管理操作审计记录。

## 9. 非功能要求

| 维度 | 首版目标 |
| --- | --- |
| 容量 | 每场 5,000 张照片 |
| 协作 | 5 名并发上传者 |
| 浏览 | 500 名并发观众、500 条 SSE 连接 |
| 性能 | 中国内地暖缓存 Fast 4G 下移动/桌面 p75 LCP 不高于 2.5 秒、INP 不高于 200ms、CLS 不高于 0.1 |
| 首屏流量 | 初始 JS/CSS gzip 后不超过 300KB，首屏媒体约束在 1.2MB 内 |
| 可用性 | API 重启后 SSE 可通过事件游标补发；上传任务可恢复已完成对象/分片 |
| 数据驻留 | 照片原图和派生文件不经过香港应用服务器 |
| 兼容性 | 观众端支持微信和现代浏览器；上传端只承诺系统 Chrome/Edge/Safari |
| 可维护性 | 单体部署、共享契约、无 Redis/微服务，媒体域名可替换 |
| OCR | 不阻塞照片发布；模型/运行时懒加载并自托管，自动候选达不到评测门槛时保持禁用 |
| 号码属性 | 确认号码确定性派生年级/班级；规则变更只重算元数据，不重新 OCR 图片 |
| 人脸找图 | 不阻塞上传/发布；每相册隔离、高精度优先、参考照与结果短期保存；未通过授权样本和云端门禁时保持关闭 |

## 10. 明确不做

- 多学校、多租户、套餐和计费；
- 公众注册、关注、评论、点赞或社交推荐；
- 除 ADR-012 明确批准的同相册人脸候选找图外的 AI 修图、内容生成、生物特征身份库、实名核身、人物画像或跨相册追踪；
- 付费下载、打赏、订单和发票；
- 批量 ZIP、打印或照片以外的媒体类型；
- 水印或云端照片格式转换；
- 微信小程序、原生 iOS/Android 客户端或桌面闪传客户端；
- 精确 CDN 播放/图片浏览日志和第三方分析平台。
- 手写/球服号码、号码到姓名映射、模糊或跨相册号码搜索。

## 11. 产品验收标准

首版只有在以下条件全部成立时才能称为可试运行：

- 一名管理员可以独立完成创建相册、邀请成员、上传、审核、发布、观看和关闭活动；
- 合规照片在正常网络下不经过业务服务器即可进入 OSS；
- 口令、角色、下载开关和 CDN 过期链接均按设计生效；
- 微信观众端不会自动下载原图；
- 未确认号码绝不进入观众搜索，号码查询不出现在 URL、日志、分析或 SSE 中；
- 号码确认后自动获得正确年级/班级；属性筛选不跨照片内不同号码拼接，人工无号码照片不会进入号码或属性结果；
- OCR 无候选不被误当成无号码，只有明确“无号码”操作可结束此类照片复核；
- 上传失败、浏览器刷新、API 重启和 SSE 断线均有明确恢复路径；
- 真实阿里云联调只产生已批准的 OSS/CDN 基础计费项；若另行启用人脸 PoC，则 IMM、EventBridge、临时 OSS、转换和索引费用必须单独对账；
- 学校已确认隐私告知、未成年人影像授权和删除投诉流程。

现有照片产品可在不实现人脸找图时满足上述试运行标准。未来启用人脸找图还必须额外满足：授权评测集没有错误人物关联、召回率单独报告；参考照/结果/整册索引按期可验证删除；跨相册和未发布照片不可返回；EventBridge 验签与重放防护通过；真实云端账单、微信/Safari 和数据出境评估均有独立证据。缺任一项时只关闭人脸找图，不降低现有照片服务的完成状态。

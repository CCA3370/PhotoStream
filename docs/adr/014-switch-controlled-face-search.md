# ADR-014：人脸找图由相册级开关直接控制

状态：Accepted；修订 ADR-012 的启用、访问类型与索引生命周期决策
日期：2026-09-07

## Context

ADR-012 在引入人脸候选找图时，为管理员启用功能设置了多层产品门禁：只允许口令相册、要求多项 readiness 确认、要求已验证阈值版本，并把全局环境开关、相册状态和索引删除生命周期与“是否允许启用”绑定。实际运行后，这些条件造成了两类问题：管理员已经明确打开相册功能时，产品仍可能因为另一个布尔值或配置字段把功能判定为关闭；公开访问、结束活动或暂时的云端故障也会修改甚至销毁管理员已经选择的功能状态。

这些策略把“管理员是否要开启功能”和“当前基础设施能否立刻完成一次检索”混成了同一个状态机。PhotoStream 现在需要一个明确的单一事实来源：相册的人脸找图开关。

本 ADR 不取消观众每次提交参考照时的单独同意，不改变参考照最小化、短期保存、结果候选表达、阿里云 IMM 数据面或明确删除整册索引的能力。

## Decision

- `album_face_indexes.enabled` 是人脸找图唯一的产品级启停事实来源。管理员在相册设置中拨动开关即生效，不需要额外保存步骤、近期认证、重新输入密码或 readiness 勾选。
- 人脸找图同时允许 `public` 和 `password` 相册。相册访问方式不得自动关闭开关、排队删除 Dataset 或改变管理员的启用选择。
- `FACE_SEARCH_GLOBAL_ENABLED` 保留为旧部署文件的兼容字段，但不再参与启动校验、功能可见性、管理员启用资格或搜索授权判断。
- `FACE_SEARCH_THRESHOLD_VERSION` 以及匹配阈值属于运行时算法配置，不再具有“qualified / unqualified”产品门禁语义。`unqualified` 值不得阻止应用启动或管理员开启功能。
- 参与者授权确认、监护人确认、影响评估、供应商资源验证、评测门禁、账单提醒、索引人脸授权等旧 readiness 字段不再出现在启用请求契约或管理端启用流程中，也不得参与 `enabled` 的派生。
- 云端凭据、IMM、临时 OSS、Dataset、索引状态和供应商故障是**运行时状态**。基础设施不完整时，管理员仍可开启开关；系统应保持 `enabled=true`，并通过 `provisioning`、`indexing`、`degraded`、`failed`、`FACE_INDEX_NOT_READY` 或 `FACE_PROVIDER_UNAVAILABLE` 等状态明确说明当前无法完成检索，而不是偷偷把功能改成关闭。
- 观众页的人脸找图入口只由相册开关决定是否存在。索引状态可以用于状态提示和实际搜索请求的运行时错误，但不得作为入口可见性的第二个开关。
- 普通“关闭人脸找图”只停止新检索、取消仍在进行的检索并清理其临时参考照/短期结果；已经建立的 Dataset 和照片索引保留，以便重新开启时直接复用。关闭开关本身不等价于删除生物识别索引。
- 重新开启时优先复用现有 Dataset 与索引；仅在 Dataset 不存在、已明确删除或需要重新 provision 时建立相应任务。
- “删除整册人脸索引”继续作为与开关分离的破坏性管理操作存在，可保留密码确认、可重试云端删除和删除确认语义。只有这个明确操作可以因为管理员请求而销毁整册 Dataset。
- 相册进入 `ended`、`archived`、恢复 `live` 或改变公开/口令访问方式，不得自动改变 `enabled`，也不得因为生命周期自动删除 Dataset。旧 `deletion_due_at` 数据可继续兼容读取，但不得作为自动关闭或自动删除依据。
- 观众每次搜索仍必须明确声明“本人”或“监护人/已获授权”，阅读本次人脸处理说明并单独同意。这是单次数据处理授权，不是管理员启用功能的前置门禁。
- 参考照仍在浏览器移除 EXIF/GPS 并转换为受限 JPEG，直传北京临时私有 OSS；同步/异步任务完成后立即删除，异常清理由既有重试和生命周期兜底。候选结果仍只表达“可能包含此人的照片”。

## Consequences

优点：管理员看到的开关与系统事实一致；不会因为相册公开、阈值标签、旧全局 flag 或某个 readiness 字段出现“界面开启、接口关闭”的双重状态；临时云端故障也不会篡改配置。关闭再开启时复用已有索引，避免无意义的整册删除和重建。

代价：`enabled=true` 不再保证运行时一定可用，管理端和观众端必须正确区分“已开启”和“当前索引/供应商不可用”。公开相册也可以提供人脸候选找图，因此部署方必须自行确保其业务授权、告知和使用范围符合实际要求；PhotoStream 不再用多项软件门禁替代这些运营责任。

保留整册索引直到管理员明确删除，会改变 ADR-012 原来的自动 30 天删除策略。部署方如需要定期清理，应通过明确的管理操作或另行设计不改变 `enabled` 事实来源的独立保留策略，而不能重新引入隐式启用门禁。

## Rejected Alternatives

- 继续保留全局开关作为总闸：会再次产生两个互相冲突的启用事实来源。
- 开关打开后只有索引 `ready` 才在观众页显示入口：这会把运行时状态重新变成隐藏的第二个启用开关。
- 关闭开关立即删除 Dataset：导致短暂关闭也触发昂贵且不可逆的重建流程，并让“关闭”和“删除”两个用户意图无法区分。
- 相册改为公开时自动关闭人脸找图：访问控制与功能配置是两个独立维度，不应互相改写。
- 继续要求管理员逐项确认 readiness：这些记录即使有运营价值，也不应由应用将其解释为产品功能的技术许可位。

## Revisit When

- 需要增加组织级策略管理，而且能够明确区分“组织策略禁止使用”和“相册管理员选择关闭”，并接受重新引入多层配置来源；
- 法律、监管或学校制度明确要求软件强制执行某个具体启用条件；
- 阿里云 IMM 的索引生命周期或删除模型发生变化，导致保留已关闭相册的 Dataset 不再可行；
- 需要设计独立的自动数据保留策略，且该策略可以在不篡改相册 `enabled` 开关的前提下工作。

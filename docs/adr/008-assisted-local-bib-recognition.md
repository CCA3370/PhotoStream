# ADR-008：号码牌采用本地自动候选与人工确认

状态：Accepted
日期：2026-08-26

## Context

学校希望观众通过号码牌筛选活动照片。纯手工输入准确但会拖慢现场工作；纯自动 OCR 可以快速建立索引，但遮挡、倾斜、背景数字和字符混淆可能把照片关联到错误学生。现有架构还要求图像不经过香港，并禁止新增云端 OCR/计算费用。

## Decision

- 使用 PaddleOCR.js 在上传者浏览器 Worker 中识别新上传照片。
- OCR 只生成候选，上传者、审核员或管理员确认后才进入公共精确搜索。
- 照片发布不等待 OCR；历史照片只手工补录。
- 每个相册使用结构化数字位置/区间规则约束候选，不允许原始正则。
- 确认号码后使用独立位置映射自动派生年级/班级；属性筛选必须在同一号码标签上匹配。
- OCR 无候选不自动判定无号码；“无号码”是人工、可撤销且与确认号码互斥的照片级结论。
- 观众搜索只用于口令相册，不展示号码目录或模糊结果。
- 号码加密保存并以相册作用域 HMAC blind index 搜索，不保存姓名映射。

## Consequences

自动候选显著减少逐张输入，人工确认消除未确认误关联进入搜索的风险；年级/班级无需重复手工填写，无号码照片也有明确终态；图像仍只在上传设备处理，阿里云只增加模型静态资源的基础存储/下行。代价是上传设备需要下载约束内的 OCR 运行时并消耗 CPU/GPU，Safari/WASM 可能较慢，人员仍需确认号码或无号码。

## Rejected Alternatives

- 完全手工：准确但批量活动工作量过高。
- 高置信结果自动入库：置信分数并非身份关联的可靠保证，学校场景风险不可接受。
- OCR 无结果自动标记无号码：漏识别会被错误固化，后续真实号码无法搜索。
- 人工填写年级/班级：容易与号码不一致，规则变化后难以批量修正。
- 云端 OCR：新增计费产品并让图像进入外部处理链路。
- 业务服务器 OCR：图片进入香港、占用 2C2G 并破坏数据边界。
- 模糊搜索：可能把近似号码的其他学生照片返回给查询者。

## Revisit When

授权样本长期无法达到自动候选验收门槛；学校允许专用内地推理资源；或未来需要手写、球服和跨相册赛事号码能力。任何升级仍必须保留人工确认作为公共索引门禁，除非学校重新批准风险模型。

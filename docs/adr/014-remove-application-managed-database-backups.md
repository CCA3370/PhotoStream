# ADR-014：移除应用管理的数据库备份

状态：Accepted
日期：2026-09-10

## Context

PhotoStream 曾包含 PostgreSQL 手动加密备份/隔离恢复工具，P1 又增加了自动备份周期、14 日 + 8 周本地保留、可选北京 OSS 异地上传和 systemd timer。用户现明确决定项目不需要应用层数据库备份功能。

## Decision

当前产品与部署基线不再提供或要求以下能力：

- PostgreSQL 逻辑备份或恢复命令；
- 应用定义的备份加密格式与密钥；
- 自动备份周期、保留策略或恢复演练；
- 备份专用 OSS Bucket、RAM 权限或上传器；
- 备份 systemd service/timer；
- 备份相关 CI guard、环境变量或部署门禁。

PostgreSQL 继续使用香港主机的 Docker named volume 持久化。数据库损坏或未来跨主机数据迁移不由 PhotoStream 内置备份工具自动处理；如确有需要，应作为新的、明确授权的运维方案单独设计。

P1 同时引入的运行时可观测性、请求延迟统计、PostgreSQL pool/SSE 指标和后台任务防重入与数据库备份无关，继续保留。

## Consequences

- 当前仓库没有应用层数据库备份或恢复执行入口。
- 部署不需要创建备份 Bucket、提供备份密钥或启用定时任务。
- 移除仓库代码不会删除任何仓库外已经存在的数据库副本、服务器文件、systemd 单元或云端对象；这些外部资源如存在，需在单独授权下处理。
- Git 历史和此前的验证/ADR 仍可能记录旧方案，作为历史证据保留；现行设计以本 ADR 和当前文档为准。

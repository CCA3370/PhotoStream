# ADR-009：采用轻量且项目可拥有的 UI 基础

状态：Accepted；由 [ADR-010](010-base-ui-and-shadcn-governance.md) 修订
日期：2026-08-26

修订说明：2026-08-27 起，ADR-010 以 Base UI 取代本文件中的 Radix UI 基座，并固定 shadcn 初始化与治理契约；本文件其余关于语义 Token、按需组件、公共端定制、虚拟化、懒加载和上传状态机的决定继续有效。以下原始决定保留用于历史追溯。

## Context

平台同时包含微信优先的公共相册、在上传设备执行重媒体任务的 PWA，以及高密度内部工作台。公共相册需要保持影像主导和较小首屏包体，工作台需要大量表单、对话框、批量选择和可访问交互。现有架构已确定 Next.js 16、React 19、服务端首屏和 300KB 初始 JS/CSS 预算，但尚未决定样式、组件原语、长列表和 UI 验证基础。

完整后台套件可以快速搭建表单和表格，却容易把公共相册做成后台风格，形成两套视觉系统，并扩大公共路由的客户端边界。完全自写 Dialog、Select、Popover 和焦点管理又会重复承担成熟可访问原语已经解决的问题。

## Decision

- 使用语义 CSS 变量定义颜色、字体、间距、圆角、层级和动效；业务组件不得以任意固定色值代替语义 Token。
- 样式工具首选 Tailwind CSS v4。进入工程阶段前，必须在支持矩阵中的真实微信 WebView、Safari 和 Chromium 上验证其官方浏览器下限；任一承诺支持的环境不满足时，在生成 UI 组件前固定回退到 Tailwind CSS v3.4，并选择经验证支持 v3.4 的 shadcn/ui 生成器/组件快照，不使用 v4 专属语法，也不在两套 Tailwind 主版本之间运行时切换。
- 使用 shadcn/ui 生成项目可拥有的组件源码，组件原语选择 Radix UI。只添加实际使用的组件并在项目内维护，不把 shadcn/ui 当成不可修改的外部主题包。
- 公共相册复用 Token、按钮、表单和对话框原语，但媒体网格、实时提示、灯箱内容与下载体验保持产品定制，不直接套用 Dashboard block。
- 表单使用 React Hook Form，客户端和服务端复用 Zod schema；客户端错误用于即时反馈，服务端继续执行最终校验和权限判断。
- 长媒体列表在约 200 个挂载卡片后使用 TanStack Virtual。TanStack Table 只用于成员、审计等语义表格，不用于照片审核网格。
- 灯箱使用项目选定的 Dialog 原语管理模态语义、焦点约束和关闭恢复，使用 Embla Carousel 管理相邻照片和触摸切换；下载授权和预取策略由项目实现。
- 公共页面保留 Server Component 主体，仅将分类、搜索、SSE 增量、灯箱和其他需要浏览器状态的区域划为小型 Client Island。灯箱、虚拟化和 OCR 模块按路由或操作懒加载。
- 上传队列继续使用本项目的多状态轴和 IndexedDB 恢复模型，不采用 Uppy Dashboard 或其状态模型。若后续评估 Uppy 的传输插件，只能复用不改变精确 OSS V4 签名、对象命名、完成校验和恢复契约的部分。
- 工程阶段使用 Storybook 固化共享组件状态，使用 Playwright + axe 执行自动无障碍检查；自动结果不能替代键盘、屏幕阅读器和真实设备人工验收。

## Consequences

优点：公共端和工作台共享一套 Token 与交互语义，公共相册仍能保持定制和小客户端边界；复杂控件获得成熟的键盘、焦点和 ARIA 基础；生成的组件源码可按学校场景修改，且只为实际使用能力付出包体。

代价：团队需要维护生成到仓库内的组件、升级时审查本地改动，并为公共媒体体验编写专用组件。Tailwind v4 的现代 CSS 下限必须在微信 WebView 上实测，不能只依据桌面浏览器或 User-Agent 判断。

## Rejected Alternatives

- Ant Design、Material UI 或 Mantine 作为全站基础：后台交付较快，但公共相册风格、客户端边界和 300KB 预算更难统一；它们不是被禁止的库，只是不作为首版基线。
- 公共端自写一套、后台使用完整组件套件：形成两套 Token、交互和无障碍维护面。
- React Aria 作为唯一原语：可访问性和定制能力充足，但首版需要自行完成更多组件视觉与组合工作；若 Radix 无法满足关键控件时可重审。
- 从原生元素开始自写全部复杂组件：Dialog、Select、Popover、Tooltip、Drawer 和焦点管理的回归风险不合理。
- Uppy Dashboard 作为上传界面：无法直接表达本地派生、预览先发布、原图续传、OCR 和照片级复核等独立状态轴。

## Revisit When

支持设备无法可靠运行所选 Tailwind 基线；公共路由实测无法达到包体或 INP 预算；Radix 在目标微信/辅助技术组合上存在无法修复的关键问题；团队无法承担项目内组件维护；或产品转为以标准后台为主、公共媒体体验不再需要定制。

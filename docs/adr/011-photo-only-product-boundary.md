# ADR-011：产品边界收缩为纯照片平台

状态：Accepted
日期：2026-08-30

## Context

早期基线把短视频上传、本地转码、海报、播放和下载列入首版，并由 ADR-006 选择浏览器 H.264/AAC 转码。阶段 5 开始前，用户明确要求彻底去掉视频适配与支持，并删除所有相关计划。当前仓库尚未实现视频上传入口，数据库中仅有为未来功能预留的类型、变体和下载开关。

## Decision

- 产品只接受、处理、审核、发布和下载照片，不接受任何视频文件或视频元数据。
- 删除视频管线文档和 ADR-006；产品需求、架构、API、UX、安全、成本、测试、路线图、部署输入与参考资料不再保留视频计划或未来占位。
- 删除数据库 `media.kind`、`media.duration_ms`、`media_kind`、相册视频下载开关和全部视频变体枚举值；共享契约、API、UI、测试和 Storybook 同步删除对应字段与分支。
- 向前迁移在发现任何异常视频媒体、变体、删除任务或统计引用时明确失败，不静默删除数据，也不把视频记录改写成照片。
- 不安装 Mediabunny、WebCodecs 适配层、ffmpeg.wasm、播放器或其他视频依赖。
- 本地对象存储保留通用 HTTP byte-range 读取能力；它服务标准对象协议测试，不构成视频上传、播放或产品支持。
- 将原安全与性能加固、部署阶段顺次前移；没有保留“稍后恢复视频”的路线图条目。

## Consequences

优点：产品、数据库和前端边界更小；避免设备转码兼容性、海报生成、视频流量、Range CDN 配置和额外验收矩阵；照片隐私与上传闭环保持单一权威路径。

代价：用户不能上传或播放活动短片；已有外部流程若依赖视频必须改用本平台之外的独立工具。数据库升级若检测到非预期视频数据会停止并要求人工确认，而不会自动继续。

## Rejected Alternatives

- 只隐藏 UI、保留数据库和 API 预留：仍形成隐性支持面，容易被误启用，也不符合“彻底去掉”。
- 保留视频文档作为未来计划：与删除相关计划的明确决定冲突。
- 继续实现合规视频直传但不转码：仍需容器验证、海报、播放、下载和设备验收，不是纯照片边界。

## Revisit When

只有用户再次明确批准视频成为产品范围，并新增替代本 ADR 的 Accepted 决策、完整产品/隐私/费用合同和独立实施阶段后才可重审；普通功能需求或技术可行性不自动恢复视频支持。
